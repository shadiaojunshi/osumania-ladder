# 谱面估算读取来源

2026-09-08：线上 `/api/osu/raw?id=5212273` 返回 `osu beatmap download failed: HTTP 429`；同一谱面在本机使用现有 Mixed 算法可正常计算。故障发生在网站下载链路。

## 修改后的行为

- 编辑页面传递 `tournamentId`、`roundId`、`slot` 和可选的 `id`（BID）。
- 优先读取 `R2_BUCKET` 中的 `maps/{tournamentId}/{roundId}/{slot}.osz`，按范围提取 `.osu`；音乐和背景留在 R2。与元数据补全接口共享归档读取模块。
- 已上传的无 BID 谱面也可估算。SV 仍排除，已有难度仍由用户点击“应用”才会更改。
- 只有 R2 文件不存在时，才按 BID 下载官网谱面。配置了 `OSU_PROXY_URL` 和 `OSU_PROXY_SECRET` 时使用代理的 `GET /osu/:id`；没有代理配置的环境仍可直连。
- 已上传文件损坏、多难度无法唯一匹配或 BID 不符时，返回 422，避免换成官网版本。R2 读取临时失败或读取期间被替换时返回 503，允许重试。
- 上传文件读取要求 contributor 权限，与现有元数据接口一致；中转下载沿用共享密钥验证。

## 缓存与重新估算

浏览器按完整请求位置缓存结果，每次估算都重新验证 R2 ETag。未变化时返回 304，复用算法结果；上传替换后 ETag 改变，重新提取并计算。不同槽位即使 BID 相同也不共用结果。切回编辑页、点击“估算本轮”都会重新验证；单图“重估”可以强制重算。不会在后台轮询或自动覆盖已填写难度。

## 发布

1. 部署 `osu-proxy/main.ts`，使代理支持新增的 `/osu/:id` 路由。
2. 部署网站前端及 Pages Functions，沿用已有 R2 绑定和代理环境变量。
3. 登录后验证已上传槽位的估算，以及一个未上传、有有效 BID 的槽位。

只更新网站时，R2 读取可生效，但尚未更新的代理不能提供新增的谱面下载路由。网站和代理均由 main 推送触发部署，两个部署都完成后整条链路才全部可用。

## 验证

`npm test` 覆盖 R2 优先、429 场景、无 BID、ZIP 压缩/存储模式、缓存重新验证、同 BID 不同上传版本、上传替换、损坏及路径输入、R2 权限和中转鉴权。前端和 Pages Functions 的 TypeScript 检查均通过。
